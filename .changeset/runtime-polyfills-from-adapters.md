Add the runtime polyfills that frameworks such as Next.js 16.2 and 16.4 need on the Azion runtime, so the adapters do not have to carry them. `Buffer.prototype.indexOf` and `lastIndexOf` (and so `includes`) accept a `Uint8Array`. `setImmediate` returns a Node-like `Immediate` (`ref()`, `unref()`, `hasRef()`) and `clearImmediate` cancels it, while the native `Immediate` is kept on a host that has one. `process.nextTick` runs the callback as a microtask (it uses `setTimeout` only when `queueMicrotask` is not available). `AsyncLocalStorage.snapshot()` and `AsyncLocalStorage.bind()` are implemented as static methods, replacing the pass-through `snapshot` of the `async-storage` polyfill. `reportError` is defined when the runtime does not have it. `queueMicrotask` is defined when the runtime does not have it (`ReferenceError: queueMicrotask is not defined`), so the callback runs as a microtask, errors thrown by it are reported and `process.nextTick` can use it. `performance.timeOrigin` follows `Date.now()` when the runtime value is not an epoch time, so `timeOrigin + now()` is a real time (it replaces the unused temporary `performance` proxy). The `setImmediate`, `reportError` and `queueMicrotask` polyfills are added to the `inject` of the preset and the `performance` entry now points to the new polyfill, which still loads `unenv/polyfill/performance` first. `@aziontech/builder` and `@aziontech/presets` are released as minor because they depend on the exact version of `@aziontech/unenv-preset`: a patch release would bring these polyfills to every project that already accepts `~1.0.x` of the builder or `~1.4.x` of the presets, without opting in.
